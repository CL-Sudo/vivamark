Request Certificate screen

A Setup screen where a Director or Attestor enrols their own certificate. Nothing is written to the database.

Not in scope: revoking or renewing certificates, and enrolment on behalf of someone else.

Context

Directors and Attestors ask support to enrol certificates for them today, which takes a day and needs a ticket each time. The enrolment service already exists; only the screen is missing.

Approach

A new applet under Setup calls the existing enrolment class. The save handler writes to the certificate store in one transaction, so a failed enrolment leaves nothing behind.

Steps

  1. Enrolment class and unit tests, autoload refresh.
  2. Applet scaffold, save handler and container page.
  3. Deploy and rollback SQL, browser verification.

Testing

Unit tests for the enrolment class, including a failed enrolment that must leave no rows. Then a staged rollout:

Risks

  • Medium The save handler touches the certificate store; a failed enrolment must leave no partial rows. Mitigation: one transaction, and a test that forces a failure halfway.
  • High The canary stage is blocked until the payments team names an owner. Mitigation: ask this week; the shadow stage does not wait for it.

Open questions

  • How long should an enrolled certificate stay valid? I assumed one year, as in the service's default.
  • Does enrolment need an audit entry of its own, or is the service's log enough?

Decisions for you

Point at an option and choose Looks good to pick it. Approving without a note here accepts the recommended options.

Where should the screen live?

  • Setup menu (recommended): next to the other self-service screens. Cost: Setup needs a new permission check.
  • User profile: where people look for their own settings. Cost: the profile page has no applet container yet.

How should it roll out?

  • Shadow, then canary, then everyone (recommended): as in the table above. Cost: about a week longer.
  • Straight to everyone, behind a feature flag. Cost: a failed enrolment would reach every Director at once.
